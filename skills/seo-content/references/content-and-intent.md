## Intent classification

Every keyword belongs to one of these intent types. Misclassify and you build the wrong page.

| Intent type | What the user wants | Page type |
|-------------|---------------------|-----------|
| **Informational** | Knowledge / explanation | Article, glossary, guide |
| **Commercial** | Compare options before deciding | Comparison guide, "best X" list |
| **Transactional** | Buy, book, apply, switch, contact now | Product page, lead form, checkout |
| **Navigational** | Specific brand/site | Homepage, brand page |
| **Local** | Location-specific help | Local landing page |
| **Problem-solving** | Pain → fix | Problem-aware article, FAQ |
| **Investigative** | Proof, reviews, legitimacy, risks | Review page, methodology, case study |

### Intent diagnostic from SERP

| Top results show... | Real intent |
|---------------------|-------------|
| Mostly guides/articles | Informational |
| Mostly comparison pages | Commercial investigation |
| Mostly product/category pages | Transactional |
| Local map pack | Local |
| Forum threads (Reddit, Quora) | Users want lived experience — write authentically |
| Videos | Visual / how-to — consider a video |
| AI Overview present | Need concise factual blocks |
| Featured snippet present | Create a snippet-targeting answer |
| People Also Ask | Use those questions as your H2s/FAQ |
| Weak/old competitors | Opportunity |
| Strong brands dominate | Need niche angle or long-tail attack |

If the SERP is dominated by a format you can't credibly produce, pick a different keyword.

## Topical authority — build clusters, not random posts

A pillar + cluster model is a common way to organise topical depth. That it ranks better than the same pages organised otherwise is `[hypothesis]` — no measured comparison backs it; use it as an organising structure, not a ranking promise.

### Example: comparison platform (electricity vertical)

```
Pillar: "Electricity comparison Portugal"
 ├── Cluster: "How electricity tariffs work in Portugal"
 ├── Cluster: "ERSE fees explained"
 ├── Cluster: "Contracted power — choosing the right kVA"
 ├── Cluster: "Bi-hourly vs simple tariff"
 ├── Cluster: "How to switch electricity provider"
 ├── Comparison: "EDP vs Galp"
 ├── Comparison: "Goldenergy vs Iberdrola"
 ├── Tool: "Electricity bill simulator"
 ├── FAQ: "Electricity switching FAQ"
 └── Local: "Best electricity provider in Algarve"
```

Each cluster page links to the pillar. The pillar links to all clusters. Comparison and tool pages link laterally to the explanatory clusters.

### Building a cluster

1. Pick the pillar topic (broad, commercially valuable).
2. List every related question (use Search Console queries, AlsoAsked, AnswerThePublic, Reddit/Quora).
3. Group questions by intent and angle.
4. One page per intent — don't merge competing intents.
5. Pillar page summarizes the topic and links out.
6. Each cluster page links back to the pillar with descriptive anchor.

## Keyword universe — categorize, don't flatten

A flat keyword list is useless. Categorize:

| Type | Example | Page that captures it |
|------|---------|----------------------|
| Head term | "electricity provider Portugal" | Pillar |
| Long-tail | "best electricity provider for bi-hourly tariff Portugal" | Cluster article |
| Pain-point | "why is my electricity bill so high" | Problem-aware article |
| Comparison | "EDP vs Galp" | Versus page |
| Alternative | "best alternative to EDP" | Alternative page |
| Local | "internet providers Algarve" | Local landing |
| Regulatory | "ERSE electricity tariff Portugal" | Glossary/explainer |
| Transactional | "switch electricity provider online" | Lead/conversion page |
| Calculator | "electricity bill simulator Portugal" | Tool page |
| Review | "Goldenergy reviews Portugal" | Review/reputation page |
| Objection | "is it safe to switch electricity provider" | Trust/FAQ page |

## Content moat — what beats generic AI content

Before writing any page, ask: *"What can this site say, show, calculate, compare, or prove that generic AI content cannot?"*

Strong moats:
- **Proprietary data** — "Average Algarve electricity bill by household type"
- **User-generated data** — anonymized comparisons across actual user inputs
- **Calculators** — bill simulator, savings estimator, eligibility checker
- **Expert review** — lawyer / accountant / sector specialist validation on the byline
- **Local knowledge** — provider performance by region, regional regulations
- **Real screenshots** — actual bills, contracts, switching steps
- **Comparison tables** — current and updated provider terms
- **Case studies** — "How João saved €312/year switching providers"
- **Interactive tools** — contract analyzer, document parser
- **Historical tracking** — price change alerts, provider reliability over time

Without a moat, you're competing with infinite AI-generated lookalikes — and losing.

## Page types and their jobs

| Page type | Role | Conversion goal |
|-----------|------|-----------------|
| Homepage | Brand/entity + main value prop | Move to category or signup |
| Pillar page | Broad authority on a topic | Move to clusters or money page |
| Cluster article | Specific intent within a pillar | Email / calculator / move to money page |
| Comparison page | Capture commercial-investigation traffic | Lead form / quote |
| Versus page (X vs Y) | Brand-to-brand decision support | Lead form / signup |
| Alternative page | Capture competitor-aware searches | Signup / trial |
| Local page | Capture regional demand | Call / contact / quote |
| Tool / calculator | Create utility, attract links | Account / email capture |
| Glossary / definition | Capture semantic terms, win snippets | Move to relevant cluster |
| FAQ page | Capture long-tail / voice / AI search | Move to money page |
| Case study | Trust + conversion | Inquiry / book demo |
| Resource hub | Internal linking + topical depth | Email signup / category page |
| Methodology page | Trust signal for comparison sites | Read offers with confidence |
| About page | Entity / brand trust | Move to product / contact |

## Title tag formula

```
Primary Keyword + Differentiator | Brand
```

Examples — **counted, because a title formula that breaks its own limit teaches the wrong thing**:

- `Best Electricity Providers in Portugal: Compare Tariffs` — **55** (no brand suffix; see the unknown-brand rule below)
- `NOS vs MEO vs Vodafone: Internet Packages Compared | MOWEI` — **58**
- `How to Switch Electricity Provider in Portugal | MOWEI` — **54**

Adding ` | MOWEI` to the first would make it **63** and break the ≤60 house target below — which is exactly when the unknown-brand rule below earns its keep: the suffix is the first thing to cut, not the last.

Rules:
- One clear primary intent — no dilution.
- Important term early.
- Include differentiator (year, region, "free", "compared", "step by step").
- ≤60 chars as a target `[unvalidated house heuristic]` — Google sets no length limit; the title link "is truncated in Google Search results as needed, typically to fit the device width" `[documented: https://developers.google.com/search/docs/appearance/title-link, 2026-10-12]`. A longer, clearer title is not a defect.
- Match page content — don't bait users.
- Avoid keyword stuffing.
- **Unknown brand?** Drop the `| Brand` suffix on intent pages — it spends scarce title relevance on a name nobody searches yet, and Google shows your brand via the Site Name attribute. Add it back once you have brand-query volume, or on navigational/brand pages.

## Meta description formula

Explain value, include proof/specifics, invite action. ≤160 chars is a target `[unvalidated house heuristic]`: "There's no limit on how long a meta description can be"; the snippet is truncated to fit the device width `[documented: https://developers.google.com/search/docs/appearance/snippet, 2026-10-12]`.

Example:
> Compare electricity providers in Portugal by kWh price, standing charge, contracted power, and loyalty terms. Find the plan that fits your usage.

Meta descriptions don't directly rank but heavily influence click-through. Write them like ad copy.

## Heading hierarchy

```
H1: Best Electricity Providers in Portugal
 H2: Quick comparison
 H2: How electricity tariffs work in Portugal
 H2: Main providers compared
  H3: EDP
  H3: Galp
  H3: Goldenergy
 H2: How to choose the best tariff
 H2: Common switching mistakes
 H2: FAQ
```

Rules:
- Single H1 per page (the page topic).
- H2 = main sections. H3 = subsections.
- Keep order clean — don't skip levels (H2 → H4). This is for accessibility, AI/snippet liftability, and UX — *not* a ranking factor: Google's parsing is fuzzy-tolerant and won't penalize skipped levels. Keep it tidy anyway; don't panic over it.
- Use real keywords in H2s, but don't stuff.

## Content elements checklist

Every SEO content page should include:

- [ ] **Direct answer near the top** — helps users + snippets + AI Overviews
- [ ] **Clear structure** — scannable H2/H3 with bullet/table-friendly sections
- [ ] **Original insight or data** — differentiation
- [ ] **Examples** — concrete, not abstract
- [ ] **Internal links** — to pillar, related clusters, money pages
- [ ] **External citations** — to regulators, primary sources, official docs
- [ ] **Visible last-updated date** — freshness signal
- [ ] **Author byline + bio** — E-E-A-T
- [ ] **FAQ section** — captures long-tail and voice/AI search
- [ ] **Conversion CTA** — matched to funnel stage

## Internal linking rules

- Use **descriptive anchors**: "compare electricity tariffs", not "click here".
- Link from cluster pages to pillar (builds topical hierarchy).
- Link laterally between related cluster pages (helps discovery).
- Link from high-authority pages to important money pages (passes authority).
- Fix orphan pages — every important URL needs inbound links.
- Don't cram keywords into anchors: Google says to "resist the urge to cram every keyword" and that "keyword stuffing is a violation of our spam policies" `[documented: https://developers.google.com/search/docs/crawling-indexing/links-crawlable, 2026-10-14]`. That over-optimised internal anchors alone draw a penalty is `[hypothesis]`; the page names no internal-anchor enforcement.

## Buyer-journey mapping

Match content to where the user is in the journey.

| Stage | Content type | Example |
|-------|-------------|---------|
| Problem unaware | Trigger awareness | "Why is my electricity bill so high?" |
| Problem aware | Educate | "How to reduce electricity bill in Portugal" |
| Solution aware | Compare options | "Compare electricity providers Portugal" |
| Provider aware | Brand-to-brand | "EDP vs Galp" |
| Decision ready | Convert | "Switch electricity provider online" |
| Retention | Re-engage | "When should I review my electricity contract?" |

A page that targets "problem-unaware" with a "decision-ready" CTA will fail — wrong message, wrong moment.

## Content scoring framework

Score every page 1-5 on each axis:

| Factor | What it measures |
|--------|------------------|
| Intent match | Does the page satisfy the actual job behind the query? |
| Topical depth | Does it cover everything a competent user expects? |
| Originality | Unique data / angle / insight not in competitor pages |
| Trust signals | Author, sources, methodology, dates |
| Structure | Scannable, well-formatted, table-ready |
| Internal linking | Connected to cluster + money pages with descriptive anchors |
| Technical health | Indexable, canonical, schema, fast |
| Conversion strength | Clear CTA, matched to funnel stage |
| Freshness | Updated within reasonable cadence for the topic |
| Competitive advantage | Beats top 5 SERP results in at least one dimension |

The 1-5 axes and the 3.5 cut-off are an `[unvalidated house heuristic]`. A page averaging below 3.5 is a **review candidate**, not a verdict: decide between improve, merge, redirect or remove only on separate evidence (its GSC clicks and impressions, inbound links, conversions, and the intent it serves).

This score ranks pages; it never clears one to ship. A page that averages 5 but carries one P0 editorial defect (a load-bearing unsourced figure, say) is blocked — see the P0–P3 filter in [publishing-gates.md](publishing-gates.md#editorial-review-p0p3) `[practitioner]`.
